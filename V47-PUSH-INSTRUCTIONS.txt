PIXEL RECALL v47 — BROAD ABO + PARTIAL FALLBACK

What changed:
- The ABO candidate pool is broad instead of requiring the old narrow title whitelist.
- The workflow still inspects at most 30,000 unique catalog images.
- IoU/NCC now rank usable patterns instead of rejecting almost everything up front.
- If fewer than 2,190 unique usable patterns survive, the build STILL deploys the best partial library.
- Partial builds are split between Daily and Run with zero overlap.
- Daily supports 3 variable-size banks; Run supports any non-empty generated pool.
- The generated-library commit no longer retriggers the expensive ABO workflow.

HOW TO APPLY TO YOUR EXISTING LOCAL GIT REPO

1. Extract this ZIP somewhere.
2. Copy ALL files/folders from the extracted v47 folder into your existing repo folder:
   C:\Users\djkau\Downloads\pixel-recall-v46-github-fix
   Choose Replace when Windows asks.

3. Open CMD in that existing repo folder.

4. Remove the two obsolete workflows if they still exist:
   git rm -f .github\workflows\deploy-pages.yml .github\workflows\generate-abo-and-deploy.yml
   If Git says a path does not exist, that is fine; continue.

5. Stage, commit and push:
   git add -A
   git status
   git commit -m "Broaden ABO generation and allow partial libraries"
   git push origin main

6. On GitHub -> Actions, watch:
   Generate ABO library and refresh Pixel Recall

A successful partial run is now valid. For example, if 1,400 unique patterns are found,
Daily and Run will both receive disjoint subsets instead of the workflow failing.
